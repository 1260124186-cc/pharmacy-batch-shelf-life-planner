# 领域说明与复算

## 配制批次

班次 t 配制一次会形成固定批量 B 的药液，批次在 t 到 t+L-1 个班次内可用。每个班次的
需求只能由已经配制且尚未失效的批次满足。未使用药液在该批次的最后一个可用班次结束时
报废，计划结束后仍在有效期内的剩余药液也一并计入报废。

方案成本只有两部分：

```text
cost = total_runs * run_cost_cents
       + total_wasted_doses * waste_cost_cents
```

逐批明细必须满足：

```text
produced_doses = runs * batch_size
produced_doses = used_doses + wasted_doses
```

## 最优次数

状态记录当前班次开始时每个剩余可用班次对应的药液量。状态有 L 个桶，桶 0 在当前班次
结束后失效，桶 L-1 可保留最久。枚举本班次 0 到 capacity 的配制次数后，把新批次加入
最晚失效桶，再按桶 0 到 L-1 的顺序消耗当前需求。结束时淘汰桶 0 并计入报废，状态所有
桶向左移动一格。

每个状态只保留总成本更低的前缀；成本相同时保留配制次数向量字典序更小的前缀。最终对
所有剩余库存补记报废成本，再比较总成本与次数向量。这个处理不依赖当前缺口贪心，也不会
忽略“提前配制可以覆盖未来需求”的情况。

## 独立复算

`tests/test_outputs.py` 中的 `reference_plan()` 只依赖实例和次数向量，使用年龄列表逐班次
执行先到期先用；`brute_force_plan()` 枚举每个班次容量范围内的全部次数组合，按

```text
(total_cost_cents, run_counts)
```

选择最小项。动态规划结果与这个枚举结果在演示实例、十班次生成实例和多个边界实例上逐字段
比对，不复用待修程序中的状态转移或合计函数。

演示数据由脚本 `solution/generate_example.py` 以固定种子生成；它用于复现实验，不表示医院
实际需求记录。
